# 2026-10-22

## The app now installs on the owner's devices

The iPhone runs iOS 18.7.8 and the iPad iOS 18.5, so the deployment target dropped from iOS 26 to 18.
Liquid Glass on the toast and the shrinking tab bar stay, behind `#available(iOS 26, *)`.
`npm run ios` now skips simulators and counts an install on a locked device as installed.

## Simpler and always light (`a6c1962`)

Feedback: "UI UX and design not simple enough, and also the color for our app shouldn't be dark."

- The dark teal (`#1B6E66`) became a bright green (`#1DA35A`), chosen for Tracy's *Eat That Frog*. Green is only for ticks, the A letter and the one primary button; red only for problems.
- The app no longer follows dark mode (`UIUserInterfaceStyle` Light).
- Screen titles moved to New York serif to match Today's date header.
- Goals went from seven sections to one list: main goal, A1 card, the rest with letters on the right, Needs a letter with a Letter menu, then Plan tomorrow and Bring in a schedule. The Today/Tomorrow switch, the goal list and the 21 dots moved one tap deeper.
- Study lost the calendar status, the budget line and the due dots, and only says a status when it needs attention.
- The Add sheet's letter picker now shows plainly which letter is chosen.

Pitfall found: setting `UINavigationBar.appearance()` in `App.init` silently replaced the green with system blue. It now happens in `AppDelegate`.

## Microsoft To Do's task details on every tab (`016ef8b`)

Request: "All tabs must have the features of Microsoft To Do, set deadline time date, notify time date, and so on."
A Haiku research agent inventoried Microsoft To Do from Microsoft's support pages; the menu wording follows it ("Remind me", "Later today", "Pick a date and time", "Add due date", "Repeat", "Add step").

- Core: `Todo` gained a due date and time, `remindAt`, `recur`, steps, a note, a star and `createdAt`; `Item` gained `remindAt`, steps and `myDay`; `Recur` gained `yearly` and `interval`. All optional, decoded leniently, so older saves and the website's backups still load.
- Ticking off a repeating to-do adds the next one (never in the past, reminder moved along, steps unticked); ticking it back on removes that untouched next one.
- Reminders are local notifications with Mark done and Remind me in 10 minutes; tapping one opens the task. Permission is asked only when a reminder is first set.
- Today: typed dates are read, five sorts, completed section, items added to Today.
- Search across tabs, list settings in More, a generated completion chime (`ios/WilList/done.wav`), an app icon badge, home-screen quick actions.

Pitfall found: on the simulator, an unanswered permission prompt from an earlier build kept reappearing after reinstalling; `xcrun simctl erase` cleared it.

The owner wants to continue on another Mac that has none of this machine's skills, settings or memory.
So the repo now carries them: `CLAUDE.md` (standing rules and commands), `docs/DESIGN.md`, `handoffs/`, `devlogs/`, the two design skills in `.claude/skills/` (MIT and Apache 2.0, licences included), and `npm run ios:shots` for simulator screenshots with sample data.

## From good to breakthrough (evening, `b9f66b3` to `2f8a2d7`)

The brief: easy to use, easy to see, easy to act on, easy to maintain; simplicity first; light with one green; ticking off fast and satisfying.
Later the owner gave full creative freedom ("design.md rules aren't a must") and said there are no fixed rules on what the app should be.
The goal prompt for the loop that drives this work is in `handoffs/GOAL.md`.

- **First run and empty states** (`b9f66b3`): a three-step welcome (what you have to do, which one matters most, your main goal) and a one-line empty state with one button on every tab.
  Four looks (`meadow`, `frog`, `notebook`, `lagoon`) live in `ios/Shared/Look.swift` for the owner to compare; debug builds only.
- **Widgets** (`143be4d`): Do this first and Today, on the Home Screen and the Lock Screen, ticked off through App Intents.
  The plan moved into the app group so the widgets read the same file.
- **CI and UI tests** (`ca36922`, `76cdba0`): the macOS job runs `swift test`, builds the app and runs the UI tests.
  Writing the first UI test found a crash: adding a to-do read the store while editing it in place, an exclusivity violation; `change` now edits a copy.
- **The A1 on Today, Goals renamed Plan** (`4e0b176`): the most important thing is the first thing you see.
  The green darkened to `#12884A` so green text reads on white.
- **Study's week** (`141be43`): plain SwiftUI bars with a dashed budget line and red only past it, instead of Charts.
- **The tick** (`842e467`): a ring and six sparks thrown off the box as it fills.
  It never showed at first: a zero-length `LinearKeyframe` before a spring made the value NaN; `MoveKeyframe` fixed it, confirmed frame by frame from a screen recording.
- **App icon** (`825e27b`): the mark in white on the green, with dark and tinted versions, drawn by `scripts/app-icon.swift`.
- **Letter sorter** (`810248a`): items waiting for a letter, one at a time, with the five letters and what each means; the last page names the A1.
- **Focus** (`8558b32`): Start on the A1 card opens one task and one ring timer; the same timer runs as a Live Activity with Mark done.
  The Live Activity vanished right after it started: the launch-time cleanup ended it, because `end()` looked up the activities asynchronously; it now captures them first.
- **Give it a letter** (`b2ff3f2`): a to-do that matters moves into Plan with its details.
  UI tests showed menu rows only answered taps on their words; `fillsRow()` makes the whole row answer.
- **Largest text sizes** (`222d0d7`): the A1 card's and focus's buttons stack instead of breaking words in half.
- **iPad** (`698ab72`): lists keep to a centred 700 pt column.
  `.safeAreaPadding` on a `NavigationStack` turned out to do nothing, and a content margin of 0 stripped a grouped list's card inset on iPhone; both are now in DESIGN.md's pitfalls.
- **Toasts and a CI flake** (`2f8a2d7`): the Mark done test failed once on CI because three slow queries outlasted the 4-second Undo toast.
  Toasts now stay five to ten seconds depending on length, VoiceOver reads them out and, with VoiceOver on, Undo waits until it's reached.
  CI prints why a UI test failed.
