## iCloud sync

The owner wants one plan on the iPhone and the iPad, through iCloud.
The plan travels as one record in the student's private CloudKit database (the whole `willist.v1` file, compressed), sent and fetched by `CKSyncEngine`, which also wakes the app when another device changed it.
The hard part is two devices changing the plan apart, so the core has `PlanMerge`, a three-way merge of the saved JSON against the copy both last agreed on.
It knows nothing of what the fields mean, so it keeps working as fields are added: what only one side changed is kept down to one field of one to-do; lists whose entries have an id are matched by it (additions land where their side put them, a delete goes unless the other side changed that thing, a reorder on one side is kept); other lists such as done dates and the focus log are bags; a field both sides changed keeps this device's change, which then goes up.
On the first sync, with nothing to compare against, a value beats an empty one, so a goal written on either device survives.
Ten tests cover it, including merging twice giving the same plan.
Records per item were the alternative; one record keeps the format the website shares and is far simpler, with a `ponytail` note on CloudKit's 1 MB record limit.
More's "Your data" footer now says whether the plan syncs, or to sign in to iCloud to turn it on.
UI tests never sync (they run on plans of their own), and the simulator has no iCloud account, so the app runs as before there.
Not yet tried with a real account: that needs the owner's Apple ID back in Xcode, after which `npm run ios` registers the container `iCloud.com.lull.willist` and push.
Older builds on the devices have no sync, so nothing changes for them until both are updated together.
