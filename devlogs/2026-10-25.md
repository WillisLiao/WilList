## The Agent works with any provider's key

**"i dont want anthropic models, i want other cheap ones, like opencode, or deepseek, or refuseless,..."**, then, before any research came back, **"realistically it should be key agnostic so the api key just provides the model, but the agent framework should be the same"**.
So the Agent no longer speaks Anthropic's Messages API: it speaks the chat completions format (OpenAI's), which nearly every provider takes, DeepSeek, OpenRouter, OpenCode Zen, Groq, Together, Mistral, Gemini's compatible endpoint and Anthropic's among them.
`Agent.Route` is now a base address, a key and an optional model: the request goes to the base followed by `/chat/completions` with the key as a bearer token, and its body holds only the system prompt, the conversation and the tools, nothing any provider could refuse (no effort, caching, beta headers, `strict` or `additionalProperties`; the app already checks every tool input itself).
The WilList server is just another such address: the App Store's signed proof is its bearer token, and it adds the model and its provider's key (`docs/AGENT-SERVER.md`, rewritten).
The assistant's message goes back in the conversation exactly as it came, so whatever a provider adds (DeepSeek's reasoning, Gemini's thought signatures) round-trips; each tool call gets its own `tool` message; a call whose arguments aren't JSON is answered "didn't match the schema", not trusted.
A reply cut off (`length`) shows "too much for one go", a filtered one or a refusal "can't help with that"; 422 joins the statuses that show the provider's own words.

Many cheap models can't see pictures (DeepSeek's can't), so only text leaves the phone now.
`fileText` reads a PDF's own text page by page, and a scanned page, like a photo, with Apple's on-device text recognition (`RecognizeTextRequest`, iOS 18); the recognized pieces are put back into lines, left to right with tabs between, so a timetable photo keeps its rows ("Monday	Quiz 3").
It runs off the main thread (`@concurrent`); the file shows as a chip with a spinner in the message field while it is read, and Send waits for it.
Photos also stop costing image tokens, and what is sent is only words.
The ask before the first message now reads "Your phone reads what you share and sends the text, with your plan, to an AI model to answer." until a provider is picked; App Store guideline 5.1.2(i) wants the AI service named, so name it there and in the privacy policy then.
Debug builds talk to a provider directly with `AGENT_URL`, `AGENT_KEY` and `AGENT_MODEL` in the scheme's environment (they replace `ANTHROPIC_API_KEY`); `-agentDemo YES` answers in the new format, and its answer no longer mentions days started with the A1 (that number left Progress earlier today).
New tests read a rendered two-row timetable photo and a PDF with a text page and a scanned page through the real recognizer, and check that the request carries nothing provider-specific.

## OpenCode for testing, and a ring around the focus timer

**"opencode"**, asked which provider the Agent should use.
OpenCode's pay-as-you-go service serves chat completions at `https://opencode.ai/inference/openai/v1` for DeepSeek V4.1 Flash ($0.30 / $1.20 per million tokens), GLM 5.3 Flash ($0.15 / $0.50), MiniMax, Kimi and Mistral; its other models answer only in other formats, and its free ones only inside OpenCode.
Its terms, though, say "You will only use the Services for your own internal use, and not on behalf of or for the benefit of any third party", the same limit found earlier on OpenCode Go.
So debug builds now default to OpenCode on `deepseek-v4.1-flash` with only `AGENT_KEY` set (for the owner's own testing, which the terms allow), and `docs/AGENT-SERVER.md` says the shipped Agent needs OpenCode's written OK or another provider.
